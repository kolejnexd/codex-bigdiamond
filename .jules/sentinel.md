## 2026-05-07 - Add missing wp_unslash() before sanitize_text_field() on $_POST data
**Vulnerability:** A superglobal (`$_POST['bdwp_engraving_text']`) was passed directly to `sanitize_text_field()` without first being processed by `wp_unslash()`. This could lead to data integrity issues or double-escaping because WordPress enforces magic quotes (adding slashes to user inputs in superglobals).
**Learning:** In the WordPress context, superglobals like `$_POST`, `$_GET`, `$_COOKIE`, and `$_REQUEST` automatically have slashes added to them by WordPress core during initialization. Calling sanitization functions like `sanitize_text_field` without first unslashing them can result in incorrectly formatted data being saved or displayed, especially if the input contains quotes or backslashes.
**Prevention:** Always apply `wp_unslash()` to variables derived from WordPress superglobals immediately before passing them to sanitization functions like `sanitize_text_field()`, `sanitize_textarea_field()`, etc., or when accessing them directly.
